# 게임 설계서

## 1. 개발 방식

- 화면 구조: HTML
- 화면 디자인: CSS
- 게임 동작: 순수 JavaScript
- 실행 환경: PC 및 모바일 웹 브라우저
- 배포 환경: GitHub Pages
- 외부 라이브러리: 사용하지 않음
- 서버 기능: 사용하지 않음
- 데이터 저장: 기본 게임 데이터는 실행 중인 브라우저 메모리에만 저장
- 개발 범위: 한 화면에서 시작, 플레이, 결과 확인, 재시작까지 가능하도록 제작

HTML은 제목과 버튼 같은 화면 요소를 만들고, CSS는 색상과 배치를 담당한다. JavaScript는 색깔 순서 생성, 사용자 입력 확인, 점수와 단계 관리 등 게임 규칙을 처리한다. 모든 파일은 정적 파일이므로 별도의 설치나 서버 없이 GitHub Pages에서 실행할 수 있다.

## 2. 프로젝트 구조

```text
MiniGame/
├── index.html
├── style.css
├── game.js
├── Images/
├── Sounds/
└── Docs/
    ├── game-plan.md
    └── game-design.md
```

- `index.html`: 게임 제목, 안내 문구, 색깔 버튼, 시작 버튼, 결과 영역 등 화면 구조
- `style.css`: 색상, 크기, 배치, 버튼 강조 효과, 모바일 반응형 디자인
- `game.js`: 게임 상태, 색깔 순서, 사용자 입력, 단계, 점수, 종료 처리
- `Images/`: 추가 장식 이미지를 넣는 폴더. MVP에서는 비워 두어도 됨
- `Sounds/`: 효과음을 추가할 때 사용하는 폴더. MVP에서는 비워 두어도 됨
- `docs/game-plan.md`: 게임의 목적과 규칙을 정리한 기획서
- `docs/game-design.md`: 파일 구조와 기능 구현 방법을 정리한 설계서

## 3. 화면 구성

| 영역 | 요소 | 역할 |
|---|---|---|
| 헤더 | 게임 제목, 한 줄 설명 | 게임의 이름과 목적을 알려준다. |
| 정보 영역 | 현재 단계, 현재 점수 | 플레이 진행 상황을 보여준다. |
| 안내 영역 | 상태 안내 문구 | 순서를 볼 때와 입력할 때를 구분해 알려준다. |
| 게임 영역 | 빨강, 파랑, 초록 버튼 | 색깔 순서를 보여주고 사용자의 입력을 받는다. |
| 제어 영역 | 게임 시작 버튼, 다시 하기 버튼 | 게임을 시작하거나 처음 상태로 되돌린다. |
| 결과 영역 | 승리·실패 문구, 최종 단계와 점수 | 게임 종료 결과를 보여준다. |

### 화면 상태별 표시

- READY: 제목, 규칙 안내, 색깔 버튼, 게임 시작 버튼을 표시한다.
- PLAYING: 단계, 점수, 상태 안내 문구, 색깔 버튼을 표시한다.
- GAME_OVER: 결과 문구, 최종 점수, 다시 하기 버튼을 표시한다.

## 4. 게임 상태

### READY

- 페이지를 처음 열었거나 다시 하기를 누른 직후의 상태다.
- 단계는 1, 점수는 0, 정답 순서와 사용자 입력은 빈 상태다.
- 색깔 버튼은 눌러도 게임 입력으로 처리하지 않는다.
- 게임 시작 버튼을 누르면 PLAYING 상태로 바뀐다.

### PLAYING

- 실제 게임이 진행되는 상태다.
- 게임이 색깔 순서를 보여주는 시간과 사용자가 답을 입력하는 시간이 모두 포함된다.
- 순서를 보여주는 동안에는 색깔 버튼 입력을 잠시 막는다.
- 순서 표시가 끝난 뒤에만 사용자의 버튼 입력을 받는다.
- 한 단계를 맞히면 10점을 더하고 다음 단계의 순서를 보여준다.
- 오답을 누르거나 5단계를 완료하면 GAME_OVER 상태로 바뀐다.

### GAME_OVER

- 게임 진행이 끝난 상태다.
- 색깔 버튼을 눌러도 점수나 순서가 바뀌지 않는다.
- 승리 또는 실패 문구와 최종 단계·점수를 표시한다.
- 다시 하기 버튼을 누르면 모든 데이터를 초기화하고 READY 상태로 돌아간다.

## 5. 주요 데이터

| 이름 | 초기값 | 역할 | 쉬운 설명 |
|---|---:|---|---|
| `gameState` | `READY` | 현재 게임 상태 | 지금이 시작 전, 플레이 중, 종료 후인지 구분한다. |
| `score` | 0 | 현재 점수 | 단계를 성공할 때마다 10씩 증가한다. |
| `level` | 1 | 현재 단계 | 1단계부터 시작하며 최대 5단계까지 진행한다. |
| `maxLevel` | 5 | 마지막 단계 | 이 값까지 성공하면 승리한다. |
| `colorSequence` | 빈 배열 | 게임이 만든 정답 순서 | 예: 빨강 → 파랑 → 빨강 순서를 차례대로 저장한다. |
| `playerSequence` | 빈 배열 | 사용자가 누른 순서 | 현재 단계에서 사용자가 누른 색깔을 저장한다. |
| `inputIndex` | 0 | 다음에 비교할 순서 위치 | 정답 배열의 몇 번째 색깔과 비교할지 기억한다. |
| `isShowingSequence` | `false` | 순서 표시 중인지 확인 | `true`일 때는 사용자가 색깔 버튼을 누르지 못하게 한다. |
| `colors` | 빨강, 파랑, 초록 | 사용할 색깔 목록 | 무작위 정답을 만들 때 이 목록 중 하나를 고른다. |

## 6. 사용자 상호작용

| 사용자 행동 | 실행 조건 | 처리 내용 | 화면 결과 |
|---|---|---|---|
| 게임 시작 버튼 클릭 | READY | 점수와 순서를 초기화하고 첫 색깔을 추가한 뒤 PLAYING으로 변경 | 1단계 순서가 표시됨 |
| 색깔 버튼 클릭 또는 터치 | PLAYING이며 순서 표시가 끝남 | 누른 색깔을 저장하고 현재 정답과 비교 | 버튼이 잠깐 강조되고 입력 결과가 처리됨 |
| 올바른 색깔 입력 | PLAYING | 다음 정답 색깔과 계속 비교 | 모든 입력이 끝나기 전까지 현재 단계 유지 |
| 한 단계의 순서를 모두 맞힘 | PLAYING | 점수 10 증가, 다음 단계 준비 | 정답 안내 후 더 긴 순서 표시 |
| 잘못된 색깔 입력 | PLAYING | 입력을 중단하고 GAME_OVER로 변경 | 실패 문구와 최종 점수 표시 |
| 5단계 순서를 모두 맞힘 | PLAYING | 점수 10 증가 후 GAME_OVER로 변경 | 승리 문구와 최종 점수 50점 표시 |
| 다시 하기 버튼 클릭 | GAME_OVER | 모든 데이터를 초기값으로 되돌리고 READY로 변경 | 시작 화면 표시 |
| 색깔 버튼 클릭 | READY 또는 GAME_OVER | 아무 게임 처리도 하지 않음 | 점수와 화면 상태 유지 |

## 7. 기능 목록

- `startGame()`: 게임을 시작한다. 모든 값을 초기화하고 1단계에 필요한 첫 색깔을 만든다.
- `addRandomColor()`: 빨강, 파랑, 초록 중 하나를 무작위로 골라 정답 순서 끝에 추가한다.
- `showSequence()`: 저장된 정답 순서를 처음부터 하나씩 보여준다. 표시 중에는 사용자 입력을 막는다.
- `highlightColor()`: 지정된 색깔 버튼을 잠깐 밝게 만들어 플레이어가 순서를 볼 수 있게 한다.
- `handleColorInput(color)`: 사용자가 누른 색깔을 받아 정답의 같은 위치와 비교한다.
- `completeLevel()`: 현재 단계를 모두 맞혔을 때 점수를 올리고 다음 단계로 진행한다.
- `endGame(isWin)`: 승리 또는 실패 결과를 정하고 GAME_OVER 화면을 표시한다.
- `resetGame()`: 단계, 점수, 순서, 안내 문구를 초기화하고 READY 상태로 돌아간다.
- `updateDisplay()`: 현재 상태에 맞게 단계, 점수, 안내 문구, 버튼 표시를 갱신한다.
- `setColorButtonsEnabled(enabled)`: 순서 표시 중이거나 게임 종료 후 색깔 버튼 입력을 막는다.

각 기능은 한 가지 역할만 맡도록 나눈다. 예를 들어 `showSequence()`는 순서를 보여주는 일만 하고, 정답 판정은 `handleColorInput()`이 담당하게 하면 초보자도 오류가 난 위치를 찾기 쉽다.

## 8. 예외 상황

- 게임 시작 버튼을 빠르게 여러 번 눌러도 게임이 중복 시작되지 않아야 한다.
- 순서를 보여주는 동안 색깔 버튼을 눌러도 사용자 입력으로 저장되지 않아야 한다.
- READY 또는 GAME_OVER 상태에서 색깔 버튼을 눌러도 점수와 단계가 변하지 않아야 한다.
- 사용자가 색깔 버튼을 매우 빠르게 연속 클릭해도 같은 입력이 중복 처리되지 않아야 한다.
- 단계가 바뀔 때 이전 단계의 사용자 입력이 남아 있지 않아야 한다.
- 다시 하기를 누르면 예약되어 있던 버튼 강조 동작이 남아서 실행되지 않아야 한다.
- 5단계 성공 후 6단계가 시작되지 않아야 한다.
- 정답 또는 실패 처리가 한 번만 실행되어 점수가 중복으로 증가하거나 결과 화면이 여러 번 표시되지 않아야 한다.
- 브라우저 창의 크기를 바꿔도 버튼이나 안내 문구가 화면 밖으로 넘어가지 않아야 한다.
- 효과음 파일이 없거나 재생되지 않더라도 게임 진행에는 영향을 주지 않아야 한다.

## 9. 반응형 조건

- PC와 모바일 모두 세로 한 화면 안에서 제목, 진행 정보, 색깔 버튼, 제어 버튼을 사용할 수 있게 한다.
- 전체 게임 영역은 너무 넓어지지 않도록 최대 너비를 정하고 PC에서는 화면 가운데 배치한다.
- 모바일에서는 화면 좌우에 작은 여백을 두고 게임 영역 너비를 화면에 맞춘다.
- 색깔 버튼은 손가락으로 누르기 쉽도록 최소 64×64픽셀 이상으로 만든다.
- 버튼 사이에는 잘못 누르는 일을 줄일 수 있도록 충분한 간격을 둔다.
- 단계와 점수, 상태 안내 문구는 작은 화면에서도 읽을 수 있는 글자 크기를 유지한다.
- 작은 모바일 화면에서는 색깔 버튼의 크기와 간격을 줄이되 가로 스크롤은 생기지 않게 한다.
- 마우스의 `hover` 효과에만 의존하지 않고 클릭·터치 시에도 버튼 강조가 보이게 한다.
- 모바일 브라우저에서 두 번 터치했을 때 화면이 불필요하게 확대되지 않도록 버튼 조작 영역을 설계한다.

## 10. 구현 순서

1. `index.html`에 제목, 단계·점수, 안내 문구, 색깔 버튼, 시작·다시 하기, 결과 영역을 만든다.
2. `style.css`에서 전체 배치와 빨강·파랑·초록 버튼의 기본 모양을 만든다.
3. JavaScript에 READY, PLAYING, GAME_OVER 상태와 주요 데이터를 만든다.
4. 게임 시작과 무작위 색깔 추가 기능을 구현한다.
5. 정답 순서를 하나씩 강조해 보여주는 기능을 구현한다.
6. 색깔 버튼 클릭·터치 입력과 정답 비교 기능을 구현한다.
7. 단계 성공, 점수 증가, 다음 단계 진행 기능을 구현한다.
8. 승리·실패와 게임 종료 기능을 구현한다.
9. 다시 하기와 전체 데이터 초기화 기능을 구현한다.
10. 모바일 반응형 디자인과 터치 편의성을 적용한다.
11. 시작부터 5단계 승리, 중간 실패, 반복 재시작 상황을 테스트한다.

## 11. 기능별 완료 조건

- [ ] 정답 색깔이 저장된 순서대로 한 번씩 강조된다.
- [ ] 순서를 보여주는 동안 사용자의 색깔 입력이 처리되지 않는다.
- [ ] 사용자가 누른 색깔과 정답의 같은 위치가 정확히 비교된다.
- [ ] 한 단계의 순서를 모두 맞히면 점수가 10점 증가한다.
- [ ] 단계 성공 후 사용자 입력이 비워지고 다음 단계가 시작된다.
- [ ] 잘못된 색깔을 누르면 즉시 실패 결과가 표시된다.
- [ ] 5단계를 완료하면 승리 결과와 최종 점수 50점이 표시된다.

- [ ] 다시 하기 버튼이 점수, 단계, 두 순서, 안내 문구를 모두 초기화한다.

- [ ] GitHub Pages에 올렸을 때 별도 설치 없이 정상 실행된다.
- [ ] PC와 모바일에서 가로 스크롤 없이 모든 주요 버튼을 사용할 수 있다.
