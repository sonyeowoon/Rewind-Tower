# Rewind Tower 게임 설계서

## 1. 개발 방식과 제한 조건

| 구분 | 방식 |
|---|---|
| 화면 구조 | HTML |
| 화면 디자인 | CSS와 CSS Grid |
| 게임 동작 | 순수 JavaScript |
| 입력 | 키보드 이벤트와 터치·포인터 이벤트 |
| 저장 | 브라우저 `localStorage` |
| 계정 확인 | Web Crypto API를 이용한 로컬 PIN 해시 비교 |
| 실행 환경 | PC 및 모바일 웹 브라우저 |
| 배포 환경 | GitHub Pages |

- 서버, 온라인 데이터베이스와 결제 기능을 사용하지 않는다.
- 로그인은 서버 인증이 아니라 현재 브라우저의 로컬 계정을 선택하고 PIN을 확인하는 기능이다.
- 사용자의 PIN 원문은 저장하지 않고 임의 salt와 해시만 저장한다.
- 설치가 필요한 라이브러리와 프레임워크를 사용하지 않는다.
- 페이지를 새로 이동하지 않고 메인 화면, 게임, 모달을 한 HTML 문서에서 전환한다.
- 시간 되감기는 과거 프레임을 재생하는 기능이 아니라 저장된 타일 좌표로 플레이어를 이동시키는 기능으로 구현한다.
- 첫 버전은 5개 고정 스테이지와 계정별 단일 진행 저장을 지원한다.
- 저장 데이터는 동일한 브라우저와 사이트 주소에서만 유지된다.

## 2. 프로젝트 파일 및 폴더 구조

```text
rewind-tower/
├── index.html
├── style.css
├── game.js
├── stages.js
├── assets/
│   ├── images/
│   └── sounds/
│       ├── bgm/
│       └── sfx/
├── docs/
│   ├── game-plan.md
│   └── game-design.md
└── README.md
```

| 파일 | 역할 |
|---|---|
| `index.html` | 로그인, 메인, 게임 화면과 조작법·튜토리얼·결과 모달의 HTML 구조 |
| `style.css` | 화면 전환, 타일, 버튼, 강조 효과와 반응형 디자인 |
| `game.js` | 로컬 계정, 상태, 맵, 이동, 수집, 되감기, 튜토리얼, 저장과 이어하기 처리 |
| `stages.js` | 5개 스테이지의 맵 배열, 이름, 설명과 해금 순서 |
| `assets/images/` | 선택적으로 사용할 캐릭터와 타일 이미지 |
| `assets/sounds/bgm/` | Suno에서 생성한 메뉴·스테이지·전체 완료 MP3 배경음 7개 |
| `assets/sounds/sfx/` | ElevenLabs에서 생성한 MP3 효과음 22개 |
| `docs/` | 기획서와 설계서 |
| `README.md` | 게임 소개, 조작법과 배포 주소 |

파일 경로는 GitHub Pages에서 동작하도록 상대 경로를 사용하고 파일명의 대소문자를 정확히 맞춘다.

## 3. 화면 영역별 구성 요소

### 3.1 로그인 화면

| 요소 | 역할 |
|---|---|
| 닉네임 입력 또는 계정 선택 | 현재 브라우저에 저장된 로컬 계정 선택 |
| PIN 입력 | 숫자 4자리 계정 확인 |
| 로그인 버튼 | 닉네임과 PIN 검증 후 메인 화면 진입 |
| 새 계정 만들기 버튼 | 닉네임, PIN, PIN 확인 입력창 표시 |
| 오류 메시지 | 형식 오류와 로그인 실패 안내 |

계정 생성 화면과 로그인 화면은 같은 영역 안에서 전환한다. PIN 입력은 화면에 그대로 노출하지 않으며, 계정 존재 여부와 PIN 오류를 하나의 일반적인 실패 문구로 안내한다.

### 3.2 메인 화면

| 요소 | 역할 | 표시 조건 |
|---|---|---|
| 제목과 한 줄 설명 | 게임 소개 | 항상 표시 |
| 현재 사용자 | 로그인한 닉네임 표시 | 로그인 후 표시 |
| 새 게임 버튼 | 초기 상태로 시작 | 항상 표시 |
| 이어하기 버튼 | 저장 데이터를 복원 | 유효한 저장이 있을 때 활성화 |
| 스테이지 선택 버튼 | 해금된 스테이지 목록 표시 | 로그인 후 표시 |
| 조작법 버튼 | 조작법 모달 열기 | 항상 표시 |
| 저장 기록 삭제 버튼 | 저장 데이터 삭제 | 저장이 있을 때 표시 |
| 음소거 버튼 | 배경음과 효과음 설정 변경 | 항상 표시 |
| 로그아웃 버튼 | 자동 저장 후 로그인 화면 복귀 | 로그인 후 표시 |
| 계정 삭제 버튼 | PIN 재확인 후 현재 계정 제거 | 로그인 후 표시 |

### 3.3 게임 화면

| 영역 | 요소 | 역할 |
|---|---|---|
| 상단 정보 | 스테이지명, 점수, 톱니바퀴, 되감기, 이동 횟수 | 게임 데이터 표시 |
| 메시지 | 저장 및 아이템 안내 | 일시적 피드백 제공 |
| 게임 영역 | CSS Grid 타일 맵 | 플레이 진행 |
| 제어 영역 | 저장, 조작법, 메인 화면 | 게임 관리 |
| 모바일 조작 | 방향 버튼, 되감기 버튼 | 터치 조작 |

### 3.4 스테이지 선택 화면

| 요소 | 역할 |
|---|---|
| 스테이지 카드 5개 | 이름, 잠금, 완료와 최고 점수 표시 |
| 진행 중 표시 | 임시 이어하기 데이터가 있는 스테이지 안내 |
| 선택 버튼 | 해금된 스테이지 시작 |
| 돌아가기 버튼 | 메인 화면 복귀 |

### 3.5 모달

| 모달 | 구성 요소 | 역할 |
|---|---|---|
| 조작법 | 키 설명, 타일 설명, 닫기 | 게임 규칙 확인 |
| 튜토리얼 | 단계 문구, 강조 표시, 다음, 건너뛰기 | 첫 플레이 학습 |
| 결과 | 승패, 최종 기록, 다시 시작, 메인 화면 | 게임 종료 처리 |
| 확인 | 새 게임 덮어쓰기 또는 저장 삭제 확인 | 실수 방지 |
| 계정 삭제 확인 | PIN 재입력과 데이터 삭제 경고 | 다른 사람 또는 실수에 의한 삭제 방지 |

조작법을 플레이 중 열면 게임 입력을 일시적으로 막는다. 모달을 닫으면 별도 게임 상태 변경 없이 다시 플레이할 수 있게 한다.

## 4. 게임 상태

핵심 게임 상태는 `READY`, `PLAYING`, `GAME_OVER`를 사용한다. 로그인 여부, 현재 화면과 모달은 별도의 데이터로 관리한다.

### READY

- 로그인하지 않았다면 로그인 화면, 로그인했다면 메인 화면을 표시한다.
- 새 게임, 이어하기와 조작법을 선택할 수 있다.
- 플레이어 이동과 되감기 입력은 처리하지 않는다.
- 저장 데이터의 유효성을 확인해 이어하기 버튼 상태를 결정한다.

### PLAYING

- 타일 맵과 상태 정보를 표시한다.
- 이동, 수집, 되감기와 저장을 처리한다.
- 튜토리얼 또는 조작법 모달이 열려 있으면 게임 입력만 일시 중단한다.
- 승리 또는 실패하면 `GAME_OVER`로 전환한다.

### GAME_OVER

- `WIN` 또는 `LOSE` 결과를 저장한다.
- 게임 입력을 차단한다.
- 결과 모달을 표시한다.
- 완료되거나 실패한 현재 스테이지의 임시 진행 저장을 삭제한다.
- 승리하면 최고 점수와 클리어 기록을 갱신하고 다음 스테이지를 해금한다.
- 다시 시작, 스테이지 선택, 다음 스테이지 또는 전체 결과 이동을 제공한다.

### 보조 화면 데이터

| 데이터 | 가능한 값 | 의미 |
|---|---|---|
| `currentScreen` | `LOGIN`, `MAIN`, `STAGE_SELECT`, `GAME` | 로그인, 메인, 스테이지 선택과 게임 화면 구분 |
| `authState` | `SIGNED_OUT`, `SIGNED_IN` | 로컬 계정 로그인 여부 |
| `currentUserId` | 없음 또는 사용자 ID | 현재 로그인한 계정 식별 |
| `activeModal` | 없음, `HELP`, `TUTORIAL`, `RESULT`, `CONFIRM` | 현재 열린 모달 구분 |
| `resultType` | 없음, `WIN`, `LOSE` | 게임 종료 결과 |

## 5. 저장해야 할 데이터

### 5.1 실행 중 데이터

| 이름 | 초기값 | 역할 |
|---|---:|---|
| `gameState` | `READY` | 현재 게임 상태 |
| `currentScreen` | `LOGIN` | 현재 보이는 화면 |
| `activeModal` | 없음 | 열린 모달 |
| `resultType` | 없음 | 승리 또는 실패 |
| `score` | `1000` | 현재 점수 |
| `moveCount` | `0` | 정상 이동 횟수 |
| `rewindCount` | `0` | 남은 되감기 횟수 |
| `rewindUsedCount` | `0` | 되감기 사용 횟수 |
| `collectedGearCount` | `0` | 모은 톱니바퀴 수 |
| `totalGearCount` | 맵에서 계산 | 전체 톱니바퀴 수 |
| `isExitOpen` | `false` | 출구 개방 여부 |
| `playerPosition` | 시작 좌표 | 플레이어의 행과 열 |
| `rewindPosition` | 없음 | 되감기 기준 좌표 |
| `mapData` | 원본 맵 복사본 | 현재 맵 상태 |
| `currentStageId` | `1` | 현재 플레이 중인 스테이지 |
| `unlockedStage` | `1` | 계정에서 선택 가능한 가장 높은 스테이지 |
| `stageRecords` | 빈 기록 객체 | 스테이지별 클리어 여부와 최고 점수 |
| `isInputLocked` | `false` | 모달과 연출 중 입력 차단 |
| `isMuted` | `false` | 음소거 여부 |
| `bgmVolume` | `0.35` | 배경음 기본 음량 |
| `sfxVolume` | `0.70` | 효과음 기본 음량 |
| `currentBgm` | 없음 | 현재 재생 중인 배경음 파일 |
| `stepSoundIndex` | `0` | 번갈아 재생할 발걸음 번호 |
| `audioUnlocked` | `false` | 사용자 입력 이후 오디오 재생 가능 여부 |

### 5.2 로컬 계정 데이터

| 필드 | 역할 |
|---|---|
| `id` | 저장을 분리하기 위한 임의의 고유 사용자 ID |
| `nickname` | 화면에 표시할 2~12자 게임용 이름 |
| `pinSalt` | 계정별 PIN 해시에 사용할 임의 값 |
| `pinHash` | Web Crypto API로 만든 PIN 검증값 |
| `createdAt` | 계정 생성 시각 |

- PIN 원문은 저장하지 않는다.
- PIN 해시는 온라인 계정 수준의 보안을 보장하지 않으며 같은 브라우저 사용자 사이의 간단한 구분만 제공한다.
- 사용자 ID는 닉네임 변경이나 비슷한 이름과 관계없이 저장 소유자를 구분하는 데 사용한다.

### 5.3 영구 저장 데이터

`localStorage`에는 서로 다른 목적의 키를 사용한다.

| 저장 키 예시 | 내용 |
|---|---|
| `rewindTower.accounts` | 로컬 계정 목록과 PIN 검증 정보 |
| `rewindTower.user.{userId}.save` | 해당 계정의 이어하기 진행 |
| `rewindTower.user.{userId}.progress` | 해금 스테이지와 스테이지별 최고 기록 |
| `rewindTower.user.{userId}.settings` | 해당 계정의 음소거와 배경음·효과음 음량 설정 |
| `rewindTower.user.{userId}.tutorial` | 해당 계정의 튜토리얼 완료 여부 |

이어하기 저장 객체에는 다음 필드를 포함한다.

| 필드 | 역할 |
|---|---|
| `version` | 저장 형식 버전 검사 |
| `userId` | 현재 로그인 계정과 저장 소유자 일치 검사 |
| `stageId` | 저장된 플레이가 속한 스테이지 |
| `savedAt` | 저장 시각 표시 및 확인 |
| `mapData` | 먹은 아이템이 반영된 현재 맵 |
| `playerPosition` | 플레이어 위치 |
| `rewindPosition` | 시간 기준점 |
| `score` | 현재 점수 |
| `moveCount` | 이동 횟수 |
| `rewindCount` | 남은 되감기 횟수 |
| `rewindUsedCount` | 사용한 되감기 횟수 |
| `collectedGearCount` | 획득한 톱니바퀴 수 |
| `totalGearCount` | 전체 톱니바퀴 수 |
| `isExitOpen` | 출구 개방 상태 |

`activeModal`, 일시적 메시지, 애니메이션 상태와 눌린 키는 저장하지 않는다.

### 5.4 스테이지 정의 데이터

각 스테이지는 `stages.js`에서 동일한 구조로 정의한다.

| 필드 | 역할 |
|---|---|
| `id` | 1부터 5까지의 고유 스테이지 번호 |
| `name` | 스테이지 선택과 HUD에 표시할 이름 |
| `description` | 핵심 퍼즐을 설명하는 짧은 문장 |
| `map` | 타일 문자로 구성된 2차원 배열 |
| `rewindLimit` | 해당 스테이지에서 얻을 수 있는 최대 되감기 수 |
| `theme` | 적용할 조명 오버레이 이름 |

스테이지 배열의 순서가 해금 순서가 되며, 각 맵은 시작점과 출구를 정확히 하나씩 포함한다.

## 6. 사용자 입력과 처리 결과

| 사용자 행동 | 실행 조건 | 처리 내용 | 화면 결과 |
|---|---|---|---|
| 새 게임 클릭 | `READY` | 새 데이터를 만들고 `PLAYING` 전환 | 게임 화면과 필요 시 튜토리얼 표시 |
| 스테이지 선택 클릭 | 로그인 상태 | 진행도 불러오기 | 5개 스테이지 카드 표시 |
| 해금 스테이지 선택 | 잠금 해제됨 | 해당 맵을 초기화하고 시작 | 선택한 스테이지 게임 화면 표시 |
| 잠긴 스테이지 선택 | 잠김 | 실행하지 않음 | 이전 스테이지 완료 안내 |
| 계정 만들기 | 로그아웃, 입력 유효 | PIN 해시 후 로컬 계정 생성 | 새 계정으로 메인 화면 진입 |
| 로그인 | 로그아웃 | 닉네임과 PIN 해시 검증 | 성공 시 해당 계정의 메인 화면 표시 |
| 로그인 실패 | 계정 또는 PIN 불일치 | 입력을 거부 | 일반 오류 문구 표시 |
| 로그아웃 | 로그인 상태 | 플레이 중이면 저장 후 현재 사용자 해제 | 로그인 화면 표시 |
| 계정 삭제 | PIN 재확인 성공 | 해당 사용자 계정과 개별 저장 삭제 | 로그인 화면 표시 |
| 기존 저장 상태에서 새 게임 클릭 | 저장 있음 | 덮어쓰기 확인 | 확인 후 새 게임 시작 |
| 이어하기 클릭 | 유효한 저장 있음 | 저장 데이터 검증 및 복원 | 저장된 위치에서 게임 재개 |
| 조작법 클릭 | 언제든 가능 | `HELP` 모달 열기 | 조작과 타일 설명 표시 |
| 조작법 닫기 | `HELP` 열림 | 모달 닫기 | 이전 화면 복귀 |
| 방향키·WASD | `PLAYING`, 입력 허용 | 다음 타일 검사 후 이동 | 위치와 상태 정보 갱신 |
| 모바일 방향 버튼 | `PLAYING`, 입력 허용 | 키보드와 같은 이동 기능 실행 | 한 칸 이동 |
| `R` 또는 되감기 버튼 | 기준점과 횟수 있음 | 위치 복원 및 횟수 차감 | 되감기 효과 표시 |
| 저장 클릭 | `PLAYING` | 현재 진행을 직렬화해 저장 | 저장 완료 메시지 |
| 메인 화면 클릭 | `PLAYING` | 최신 상태 저장 후 `READY` 전환 | 이어하기가 있는 메인 화면 표시 |
| 저장 기록 삭제 | 저장 있음 | 확인 후 진행 저장 삭제 | 이어하기 비활성화 |
| 튜토리얼 다음 | 단계 조건 완료 | 다음 단계로 이동 | 새 안내와 강조 표시 |
| 튜토리얼 건너뛰기 | 튜토리얼 중 | 완료 여부 저장 및 종료 | 정상 플레이 전환 |
| 열린 출구 진입 | 모든 톱니 수집 | 승리 처리 및 진행 저장 삭제 | 결과 모달 표시 |
| 시간 균열 진입 | `PLAYING` | 실패 처리 및 진행 저장 삭제 | 결과 모달 표시 |

사운드는 위 행동 처리에 성공한 뒤 재생한다. 이동 실패에는 발걸음 대신 `move-blocked.mp3`만 사용하며, 모래시계 획득음과 기준점 생성음은 애니메이션 단계에 맞춰 순서대로 재생한다.

## 7. 기능 목록과 역할

함수명은 구현을 정리하기 위한 이름이며 실제 코드 작성 시 조정할 수 있다.

## 8. 오류를 예방하기 위한 예외 상황

### 입력과 화면

- `PLAYING` 상태가 아니거나 모달이 열려 있으면 게임 입력을 처리하지 않는다.
- 방향키로 페이지가 스크롤되지 않도록 게임 중 기본 동작을 막는다.
- 키를 길게 눌러 지나치게 빠르게 이동하지 않도록 입력 간격을 제한한다.
- 모달이 여러 개 동시에 열리지 않도록 `activeModal`을 하나만 허용한다.
- 플레이 중 조작법을 닫으면 기존 게임 데이터가 초기화되지 않아야 한다.

### 맵과 이동

- 맵 바깥, 벽과 닫힌 문으로는 이동할 수 없다.
- 실패한 이동은 횟수와 점수를 변경하지 않는다.
- 플레이어 시작점과 출구는 각각 하나만 존재해야 한다.
- 맵의 모든 행 길이는 같고 가장자리는 벽으로 둘러싸여야 한다.
- 획득한 아이템은 같은 위치에서 두 번 처리되지 않아야 한다.

### 되감기

- 기준점이 없거나 횟수가 0이면 되감기를 실행하지 않는다.
- 이미 기준점에 있다면 되감기 횟수를 소비하지 않는다.
- 되감기 횟수는 0 미만 또는 최대 3회를 초과하지 않는다.
- 되감기 중 입력을 잠깐 잠가 중복 실행을 막는다.
- 복원 위치가 맵 범위 안의 이동 가능한 타일인지 확인한다.
- 되감기 후 획득 아이템과 출구 상태는 유지한다.

### 튜토리얼

- 튜토리얼 도중 새 게임이나 메인 화면으로 이동하면 입력 잠금이 남지 않아야 한다.
- 단계 완료 이벤트가 여러 번 들어와도 한 단계만 이동해야 한다.
- 건너뛰기와 완료는 동일하게 완료 여부를 저장한다.
- 튜토리얼 저장을 읽지 못하면 첫 실행으로 보고 게임 진행은 허용한다.
- 이어하기에서는 저장된 진행을 변경할 수 있으므로 튜토리얼을 자동 실행하지 않는다.

### 저장과 이어하기

- `localStorage` 사용이 차단되거나 용량 오류가 발생하면 게임은 계속되고 저장 불가 안내만 표시한다.
- JSON 변환에 실패한 저장은 불러오지 않는다.
- 저장 버전이 현재 게임과 다르면 이어하기를 비활성화하고 새 게임을 안내한다.
- 로그인하지 않은 상태에서는 게임 저장과 불러오기를 실행하지 않는다.
- 저장 객체의 `userId`가 현재 사용자 ID와 다르면 절대 불러오지 않는다.
- 저장 객체의 `stageId`가 존재하는 1~5 범위인지 확인한다.
- 잠긴 스테이지 ID를 주소나 개발자 도구로 요청해도 시작하지 않는다.
- 해금 단계는 1보다 작거나 전체 스테이지 수보다 커지지 않게 제한한다.
- 최고 점수는 기존 점수보다 높을 때만 교체한다.
- 모든 진행, 튜토리얼과 설정 키에는 현재 사용자 ID를 포함한다.
- 숫자 값이 음수이거나 좌표가 맵 밖이면 손상된 저장으로 판단한다.
- 저장된 맵 크기와 현재 스테이지 맵 크기가 다르면 불러오지 않는다.
- 필수 필드가 없으면 기본값을 임의로 섞지 않고 저장을 무효화한다.
- 자동 저장 도중 오류가 나도 이동이나 수집 결과를 취소하지 않는다.
- 저장 완료 전에 여러 저장 요청이 들어오면 마지막 정상 상태만 저장한다.
- 게임 종료 후 진행 저장을 삭제하되 튜토리얼 및 설정 데이터는 유지한다.
- 새 게임으로 기존 저장을 덮어쓰기 전 확인 절차를 제공한다.

### 계정과 PIN

- 빈 닉네임, 2자 미만, 12자 초과 및 허용하지 않은 문자가 포함된 닉네임은 거부한다.
- 앞뒤 공백을 제거하고 비교용 닉네임을 통일해 중복 생성을 막는다.
- PIN은 숫자 4자리만 허용하고 확인 PIN이 다르면 생성하지 않는다.
- PIN 원문을 콘솔, HTML 속성 또는 `localStorage`에 남기지 않는다.
- Web Crypto API를 사용할 수 없으면 계정 생성을 중단하고 지원 브라우저 안내를 표시한다.
- 여러 번 로그인 버튼을 눌러도 동시에 중복 로그인 처리가 실행되지 않아야 한다.
- 로그아웃할 때 다른 계정의 메인 화면이나 저장 데이터가 잠깐 표시되지 않게 화면을 먼저 잠근다.
- 계정 삭제는 현재 PIN 재확인과 경고 확인을 모두 요구한다.
- 계정 삭제 시 현재 사용자 ID로 시작하는 키만 삭제하고 다른 계정 데이터는 보존한다.
- 로컬 계정은 보안 인증이 아니라는 점과 브라우저 데이터 삭제 시 복구할 수 없다는 점을 화면에 안내한다.
- 현재 로그인한 사용자 ID는 실행 중 메모리에만 두며 페이지를 새로 열면 다시 로그인하도록 한다.

### 리소스

- 이미지 로딩 실패 시 배경색, 텍스트 또는 이모지로 구분할 수 있어야 한다.
- 배경음 또는 효과음 로딩·재생 실패가 게임 동작을 중단시키지 않아야 한다.
- 사용자의 첫 클릭 전에는 브라우저가 오디오를 차단할 수 있으므로 버튼 조작 후 재생한다.
- 배경음 교체 전 현재 곡을 일시정지하고 재생 위치를 0으로 돌려 중복 재생을 막는다.
- 동일한 짧은 효과음이 연속 입력으로 겹치지 않도록 효과음별 최소 재생 간격을 둔다.
- `play()`가 반환한 재생 실패는 처리하되 콘솔 오류로 게임 흐름을 중단하지 않는다.
- 메뉴로 돌아갈 때 스테이지 배경음이 남아 있지 않아야 한다.
- 음소거 중 새 화면으로 전환해도 배경음이 갑자기 재생되지 않아야 한다.
- 계정을 바꾸면 해당 계정의 음소거와 음량 설정을 다시 적용한다.
- 마지막 스테이지 완료 시 `all-clear.mp3` 재생 후 약 1초 뒤 `bgm-all-clear.mp3`를 시작해 두 소리가 강하게 충돌하지 않게 한다.

## 9. PC와 모바일 반응형 조건

- 360픽셀 너비 이상에서 가로 스크롤 없이 플레이할 수 있어야 한다.
- 맵은 화면 너비에 맞춰 축소하고 타일은 정사각형 비율을 유지한다.
- PC에서는 키보드를 기본으로 하고 모바일 조작 버튼은 숨기거나 보조 표시한다.
- 터치 환경에서는 방향 버튼과 되감기 버튼을 표시한다.
- 터치 버튼은 최소 약 44×44픽셀로 만든다.
- 상태 정보가 좁은 화면에서는 두 줄로 재배치된다.
- 튜토리얼과 조작법 모달은 화면 높이를 넘으면 모달 내부만 스크롤된다.
- 모바일 튜토리얼은 키보드 키 대신 화면 버튼도 함께 강조한다.
- 세로 화면을 기본으로 하되 가로 화면에서도 맵과 핵심 버튼이 잘리지 않아야 한다.
- 안전 영역이 있는 모바일 기기에서는 하단 버튼에 여백을 둔다.

## 10. 기능 구현 순서

1. HTML에 로그인, 메인, 스테이지 선택, 게임 화면과 모달 구조를 만든다.
2. CSS로 화면 전환, 타일 Grid와 반응형 기본 배치를 만든다.
3. 로컬 계정 생성, PIN 해시, 로그인과 로그아웃을 구현한다.
4. `READY`, `PLAYING`, `GAME_OVER` 및 보조 화면 상태를 만든다.
5. `stages.js`에 5개 맵과 스테이지 정보를 정의한다.
6. 선택한 2차원 배열 맵을 화면에 표시한다.
7. 방향키·WASD 이동과 벽·경계 충돌을 구현한다.
8. 톱니바퀴 수집, 점수와 출구 개방을 구현한다.
9. 모래시계, 기준점과 되감기를 구현한다.
10. 무너지는 발판, 열쇠와 잠긴 문을 구현한다.
11. 시간 균열, 승패와 결과 모달을 구현한다.
12. 스테이지 선택, 순차 해금과 최고 점수를 구현한다.
13. 메인 화면의 조작법 모달을 구현한다.
14. 1번 스테이지 튜토리얼과 행동 완료 판정을 구현한다.
15. 사용자별 수동 저장, 자동 저장과 데이터 검증을 구현한다.
16. 메인 화면의 이어하기, 로그아웃과 계정 삭제를 구현한다.
17. 두 개 이상의 테스트 계정으로 진행도 분리를 확인한다.
18. 모바일 화면 버튼과 반응형 디자인을 완성한다.
19. 배경음 7개와 효과음 22개의 파일 경로 및 재생 함수를 연결한다.
20. 음소거, 계정별 음량 설정과 중복 재생 방지를 구현한다.
21. 선택 애니메이션을 추가한다.
22. 새로고침, 손상 저장, 사운드 실패, PC·모바일 및 GitHub Pages 환경을 테스트한다.

핵심 게임을 먼저 완성한 뒤 튜토리얼과 저장을 연결해야 문제 발생 위치를 쉽게 찾을 수 있다.

## 11. 기능별 완료 조건

### 로컬 계정

- [ ] 유효한 닉네임과 4자리 PIN으로 계정을 생성할 수 있다.
- [ ] 중복 닉네임과 잘못된 PIN 형식을 거부한다.
- [ ] PIN 원문이 저장소와 콘솔에 남지 않는다.
- [ ] 올바른 PIN으로만 로그인할 수 있다.
- [ ] 로그인한 닉네임이 메인 화면과 게임 화면에 표시된다.
- [ ] 로그아웃하면 로그인 화면으로 돌아가고 현재 사용자 데이터가 메모리에서 제거된다.
- [ ] 계정 삭제 시 PIN을 다시 확인한다.
- [ ] 계정 삭제가 다른 계정에는 영향을 주지 않는다.
- [ ] 로컬 계정의 한계가 로그인 화면에 안내된다.

### 기본 화면과 상태

- [ ] 메인 화면과 게임 화면이 한 페이지에서 전환된다.
- [ ] 상태에 맞지 않는 게임 입력이 처리되지 않는다.
- [ ] 모달은 한 번에 하나만 표시된다.
- [ ] 스테이지 선택 화면에 5개 카드가 표시된다.
- [ ] 잠긴 스테이지는 시작할 수 없다.
- [ ] 클리어 시 다음 스테이지와 최고 점수가 저장된다.

### 조작법

- [ ] 메인 화면에서 조작법 버튼을 누르면 모달이 열린다.
- [ ] 키보드와 모바일 조작, 되감기 및 주요 타일 설명이 보인다.
- [ ] 닫기 버튼, 바깥 영역 클릭과 `Esc`로 닫을 수 있다.
- [ ] 플레이 중 열고 닫아도 진행 데이터가 유지된다.

### 튜토리얼

- [ ] 첫 새 게임에서 튜토리얼이 자동으로 시작된다.
- [ ] 이동, 톱니 수집, 모래시계와 되감기 단계가 순서대로 표시된다.
- [ ] 각 단계의 요구 행동을 완료해야 다음 단계로 진행된다.
- [ ] 건너뛰기 버튼이 작동한다.
- [ ] 완료 또는 건너뛰기 여부가 브라우저에 저장된다.
- [ ] 이후 새 게임에서는 자동으로 반복되지 않는다.
- [ ] 조작법 화면에서 튜토리얼을 다시 시작할 수 있다.
- [ ] 이어하기에서는 튜토리얼이 강제로 실행되지 않는다.

### 이동과 퍼즐

- [ ] 방향키, WASD와 모바일 버튼으로 한 칸씩 이동한다.
- [ ] 벽과 맵 바깥 이동이 차단된다.
- [ ] 톱니바퀴와 모래시계를 한 번만 획득한다.
- [ ] 되감기 사용 시 플레이어 위치와 횟수만 변경된다.
- [ ] 수집 상태와 출구 상태는 되감기 후에도 유지된다.
- [ ] 모든 톱니바퀴를 모으면 출구가 열린다.
- [ ] 열린 출구는 승리, 시간 균열은 실패를 발생시킨다.
- [ ] 3번 스테이지의 발판은 한 번 통과한 뒤 무너진 상태로 바뀐다.
- [ ] 4번 스테이지의 열쇠를 얻으면 잠긴 문을 통과할 수 있다.
- [ ] 5번 스테이지는 앞선 핵심 퍼즐을 함께 사용한다.
- [ ] 마지막 스테이지 완료 시 전체 클리어 결과가 표시된다.

### 저장과 이어하기

- [ ] 저장 버튼을 누르면 현재 진행이 저장된다.
- [ ] 정상 이동, 수집, 되감기와 출구 개방 뒤 자동 저장된다.
- [ ] 저장 성공 여부가 짧은 메시지로 표시된다.
- [ ] 저장이 있을 때만 이어하기가 활성화된다.
- [ ] 현재 로그인 계정의 저장만 이어하기 대상으로 확인한다.
- [ ] 새로고침 후 이어하기로 맵, 위치, 점수와 횟수가 복원된다.
- [ ] 이어하기 직후 게임 상태가 `PLAYING`이 된다.
- [ ] 저장 삭제가 확인 절차 후 작동한다.
- [ ] 종료된 판의 진행 저장은 삭제된다.
- [ ] 튜토리얼 및 음소거 설정은 진행 저장 삭제 후에도 유지된다.
- [ ] 계정 A와 계정 B의 진행, 튜토리얼과 설정이 서로 분리된다.
- [ ] 계정 A와 계정 B의 스테이지 해금 및 최고 점수가 서로 분리된다.
- [ ] 저장된 스테이지 ID에 해당하는 정확한 맵이 복원된다.
- [ ] 손상되거나 버전이 다른 저장 데이터는 안전하게 거부된다.
- [ ] 저장 기능이 차단되어도 게임 자체는 계속 플레이할 수 있다.

### 재시작과 결과

- [ ] 승리와 실패 결과가 서로 다르게 표시된다.
- [ ] 최종 점수, 이동 횟수, 수집 수와 되감기 사용 수가 표시된다.
- [ ] 다시 시작하면 새 맵과 초기 데이터로 시작한다.
- [ ] 메인 화면으로 돌아가면 정상적인 버튼 상태가 표시된다.

### 사운드
