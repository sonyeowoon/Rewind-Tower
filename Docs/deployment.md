# 배포 준비와 검증 기록

## 배포 결과물

`npm run build`는 제공 이미지 15개와 추가 생성 배경 1개, 사운드 29개와 런타임 파일 9개를 `dist/`에 준비합니다. 기획서, 테스트, 로컬 서버, 원본 스타일 참고판 등은 배포 대상에서 제외합니다. 외부 API 키, 서버, 데이터베이스가 필요하지 않습니다.

`release.json`에는 버전과 파일 목록을 기록합니다. 소스 또는 리소스 내용이 바뀌면 버전이 변경됩니다. 게임의 저장 형식 `version: 2`은 배포 파일 버전과 독립적입니다. 10층 개편 전 버전 1의 임시 이어하기는 거부하며, 계정·최고 기록·해금·설정은 유지합니다.

## GitHub Pages

- 포함된 `.github/workflows/pages.yml`은 기본 브랜치에서만 배포합니다. PR과 다른 브랜치는 테스트·패키징을 수행합니다.
- 저장소의 Pages Source를 GitHub Actions로 설정해야 합니다.
- 사이트를 공개할 저장소, 접근 권한과 Pages 설정은 아직 연결하지 않았습니다.
- 사용자 사이트의 `/`와 프로젝트 사이트의 `/<repository>/` 모두를 고려한 상대 경로입니다.
- `.nojekyll`을 포함하고, 배포 출력의 최상위에 `index.html`을 둡니다.
- 대소문자를 구분하는 Linux 배포를 위해 실제 파일명과 참조의 일치를 자동 검사합니다.

근거: [GitHub Pages 유형과 경로](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [사용자 정의 배포 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## GPT Sites

설치된 Sites 호스팅 스킬의 정적 호스팅 계약을 기준으로, 빌드 명령은 `npm run build`, 정적 출력 폴더는 `dist`로 준비했습니다. 실제 사이트 등록이 완료된 뒤 `.openai/hosting.json`의 실제 `project_id`와 `static.directory: "dist"`를 연결해야 합니다. 가짜 ID나 미등록 사이트용 활성 설정 파일은 만들지 않았습니다.

이 프로젝트는 서버 런타임 바인딩, 인증 API, D1 또는 R2 없이 정적 파일로 동작합니다. 실제 Sites 접근 권한, 배포 URL, 서비스 측 응답 헤더와 미리보기 프레임 정책은 아직 서비스에 배포하지 않았으므로 현지 검증 결과로 단정하지 않습니다.

## 수정한 배포 관련 위험

| 위험 | 대응 |
|---|---|
| 배포 갱신 후 이전 JS/CSS 캐시가 섞임 | 내용 해시 파일명과 버전이 포함된 리소스 URL |
| 저장소 하위 주소에서 이미지·음악 경로가 어긋남 | 상대 모듈 import와 `import.meta.url` 기준 리소스 주소 |
| 이미지 URL에 버전 쿼리가 붙으며 CSS 자르기가 풀림 | 파일명 포함 선택자로 수정, 배포본 화면 확인 |
| Windows에서 성공한 파일 경로가 Linux에서 실패 | 대소문자까지 일치하는 파일 목록 검사 |
| 배포에 개발용 파일이 포함되거나 런타임 파일이 빠짐 | 명시적인 배포 파일 목록과 의존 경로 검사 |
| 브라우저 저장 제한·용량 오류로 게임이 멈춤 | 현재 창의 메모리 저장과 지속적인 저장 불가 안내 |
| PIN 검증 API가 지원되지 않는 환경 | 계정 생성 거부와 localhost/HTTPS 안내 |
| 오디오 재생이 거부되며 입력 처리가 멈춤 | 동기 오류와 Promise 거부를 모두 처리 |
| 배경으로 보낸 창에서 지연 효과음이 재생됨 | 오디오 일시 중단 상태를 모든 재생에 적용 |
| 모래시계와 기준점 효과음이 겹침 | 모래시계 획득 연출 종료 후 해당 효과음을 멈추고 기준점 효과음 재생 |
| 여러 창의 동일 프로필이 최신 진행을 덮어씀 | 다른 창의 저장 변경 감지 후 이전 플레이 세션 해제 |
| 다른 창에서 삭제한 계정의 저장이 다시 생김 | 계정 삭제 감지 시 추가 저장 없이 세션 해제 |

## 검증 범위

- 순수 규칙 및 배포 테스트 24개 통과.
- Chrome의 실제 키보드 입력으로 10층 전체 클리어, 균열 실패, 결과와 다음 층 해금 확인.
- 가입, 잘못된 PIN, 튜토리얼 5단계, 모달 입력 차단, 새로고침 후 로그인·이어하기 확인.
- 두 계정의 진행·설정 분리, PIN을 재확인하는 삭제, 손상 저장 거부 확인.
- 360px 화면에서 가로 넘침 없이 터치 버튼으로 이동 확인.
- 배포본을 `/rewind-tower/` 하위 경로에서 실행하고 동일한 전체 흐름 검증.
- 저장소 차단, 용량 오류, 오디오 동기 예외·Promise 거부, Web Crypto 미지원 시나리오 확인.
- 실제 반복 경로의 역순 재생과 재생 중 저장·화면 이동·새로고침, 모션 감소 설정 확인.
- 10개 층의 BGM을 5곡에 두 층씩 연결하고 모바일 맵 확대 확인.
- 같은 계정의 다중 창과 다른 창에서의 계정 삭제 시나리오 확인.

실제 Safari/iOS 기기, 실제 Sites 배포 및 실제 GitHub Pages URL에서는 아직 확인하지 않았습니다. 서비스 연결 후에는 해당 URL에서 첫 가입·저장·새로고침·오디오와 터치 입력을 확인하면 됩니다.

## 주소가 달라질 때의 저장

Sites와 GitHub Pages는 서로 다른 출처(origin)입니다. 같은 닉네임과 PIN을 사용해도 두 주소의 기록이 자동으로 이동하지 않습니다. 이는 기획서의 브라우저 로컬 저장 방식에 따른 동작입니다. 미리보기 주소와 정식 주소가 달라도 마찬가지입니다. 데이터 내보내기/가져오기는 현재 구현 범위에 포함하지 않았습니다.

Web Crypto와 로컬 저장을 쓰는 게임이므로 HTTPS 정식 주소 또는 localhost에서 실행해야 합니다. iframe의 저장소 정책에 막히는 경우 현재 창의 임시 플레이로 전환하며, 영구 기록은 사이트의 직접 주소에서 확인해야 합니다.
